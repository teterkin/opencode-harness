## [Unreleased]

## [2.8.0] — 2026-11-23

### Added

- Правило 5 `AGENTS.md`: объявленная проектом проверка безопасности
  запускается как тесты; невыполнимая называется одной строкой, сохранённая
  находка записывается с причиной.
- Правило 7 `AGENTS.md`: вендоренный и скачанный код проверяется по версии и
  чек-сумме до использования; исполнение через `eval`, `new Function`, `vm` —
  только после проверки, fail closed.
- `docs/prd/2.8.md`.
- README и `docs/workflow.md`: SAST, secret scanning и SCA — не
  ответственность харнесса, их место в CI/CD; правило требует запускать
  заявленную проверку, а не поставлять сканеры.

### Changed

- Харнесс проверен на opencode 2.4.0: `opencode.version` обновлён, минимум
  остаётся 2.3.0. `tests/doctor.bats.sh` читает пин, а не зашивает версию.

## [2.7.0] — 2026-11-16

### Added

- `docs/prd/2.7.md`: ревью зафиксировано как один ручной проход; авто-цикл
  «нашёл → починил → перетестил» и `/goal` — явные non-goals.

### Changed

- Правило 5 `AGENTS.md`: ревью — отдельный проход, а не цикл. Находки идут
  пользователю, исправления — после его решения, повторный `/review` — по
  просьбе.
- `commands/review.md` требует сначала показать находки и не менять код до
  решения пользователя.
- `docs/workflow.md` и README описывают контракт ревью и называют отсутствие
  автоматического цикла решением.
- `tests/docs.bats.sh` проверяет формулировки и отсутствие `/goal` в командах.

## [2.6.0] — 2026-11-15

### Added

- `skills/project-kit`: раздел «Repository metadata» — требования к
  `description`, `homepage`, `topics` и `visibility`, команды чтения и записи.
- `tests/repo-meta.sh` — opt-in проверка метаданных на GitHub: непустой
  `description`, 5–10 topics в kebab-case без дублей, `homepage` пустой или
  `https://`. Коды выхода `0/1/2/3`.
- Правило 9: метаданные репозитория входят в docs-baseline.
- Репозиторий заполнен: русское описание и 7 topics.

## [2.5.0] — 2026-11-15

### Changed

- Правило 6 переписано как процесс из семи шагов: план → подтверждение плана →
  тесты, код и доки → аппрув результата → коммит → пуш → релиз. Каждый шаг
  требует отдельного согласия; подтверждённый план не разрешает коммит, коммит
  не разрешает пуш, пуш не разрешает релиз. Один пуш может содержать несколько
  коммитов.
- `/release` больше не считается согласием на пуш рабочих коммитов: он покрывает
  версию, `CHANGELOG`, тег, пуш тега и публикацию релиза.
- `git push` в `permissions` — `ask`, и правило прямо называет его страховкой, а
  не согласием: клик в диалоге не заменяет просьбу в чате.
- `agents/implementer.md` и `commands/release.md` следуют тем же гейтам, README и
  `docs/workflow.md` описывают процесс.

## [2.4.1] — 2026-11-15

### Added

- `docs/workflow.md`: раздел «Проверка границы» — ручной чек-лист из трёх ловушек
  (соседний репозиторий, запись вне проекта, самостоятельный коммит), критерии
  «плюс/минус» и список того, что прислать с прогона.

## [2.4.0] — 2026-11-15

### Added

- `install.sh` предупреждает, если домашний каталог сам является
  git-репозиторием: проекты внутри него не получают собственный репозиторий, а
  `git add -A` затянет `.ssh` и `.git-credentials`.

### Changed

- Правило 6 смотрит на корень репозитория (`git rev-parse --show-toplevel`), а не
  на факт его существования. Если корень — родитель рабочего каталога, особенно
  `$HOME` или `/`, у проекта нет своего репозитория: агент делает `git init` на
  месте. `git add -A`, `git add .` и `git commit -a` в таком репозитории
  запрещены.

## [2.3.0] — 2026-11-15

### Added

- Правило 13: агент работает только в каталоге сессии. Подниматься в
  родительский каталог, уходить в соседний репозиторий и искать «репозиторий
  получше» вместо пустого рабочего каталога запрещено; чужая задача —
  остановиться и спросить.
- `opencode.json` включает `external_directory: ask`: любой путь вне проекта —
  чтение и запись — требует подтверждения.
- У `implementer` `git commit*`, `git push*` и `git tag*` теперь `ask`, а не
  `allow`.

### Fixed

- Из правила 12 убрана личная настройка автора (конкретный MCP-сервер и пути к
  его проектам): она попадала в git и ставилась каждому пользователю. Теперь
  правило говорит, что состав MCP-серверов — дело машины и проекта, и личные
  заметки живут вне маркеров харнесса.
- В шаблоне проектного `AGENTS.md` появился раздел про локальные заметки.

## [2.2.0] — 2026-11-15

### Added

- `install.sh --dry-run` печатает план установки — какие файлы будут созданы,
  обновлены и удалены, и какие ключи появятся или изменятся в
  `opencode.json` — и ничего не пишет: ни бэкапа, ни манифеста, ни правок
  `AGENTS.md`. План строится прогоном установщика в staging-копии конфига,
  поэтому не может разойтись с реальным поведением.

### Fixed

- Устаревший совет «выйди из opencode и запусти заново» заменён на `/reload`:
  начиная с 2.x конфиг, агенты, команды и скиллы перечитываются сами.
- `opencode.json` проверяется на валидный JSON до первой записи: при битом
  файле установка больше не оставляет частично скопированные агенты и скиллы.

## [2.1.0] — 2026-11-15

### Changed

- `install.sh` ставит `model` и `default_agent` только если их ещё нет в
  `opencode.json`: выбранные пользователем модель и агент больше не
  перезаписываются ни при установке, ни при обновлении. Дефолты остались
  прежними — `opencode/big-pickle` и `implementer`.
- Шаблон `opencode.json` в репозитории больше не задаёт `model` и
  `default_agent`: проектный конфиг перебивал глобальный выбор модели для всех
  агентов без своего `model`.

## [2.0.1] — 2026-11-15

### Fixed

- `install.sh` больше не перезаписывает `AGENTS.md` целиком: правила харнесса
  живут между маркерами `<!-- harness:begin -->` и `<!-- harness:end -->`,
  пользовательский текст вне них сохраняется. Файл без маркеров (установка
  2.0.0) мигрирует в один блок без дублирования правил.
- `uninstall.sh` вырезает из `AGENTS.md` только блок харнесса и удаляет файл,
  только если в нём ничего не осталось.

## [2.0.0] — 2026-11-15

Переход на opencode 2.x. Несовместимо с 1.x: минимальная версия — 2.3.0,
правила прав переписаны на формат v2.

### Added

- `tests/doctor.sh` — сверяет запущенную версию opencode с пином
  `opencode.version` и ищет рядом более новый бинарь. Коды выхода: `0` —
  совпадает, `1` — ниже минимума, `2` — дрейф с прогоном самотестов.
- `tests/doctor.bats.sh` — симуляции версий, путей и старого формата вывода.
- `tests/version.bats.sh` — `VERSION` = верх `CHANGELOG.md` = тег; режим
  `--tag` требует существующий аннотированный тег.
- `tests/docs.bats.sh` — docs-baseline, порядок секций README, шаблоны.
- `VERSION` и `opencode.version` — версия харнесса и пин инструмента.
- `commands/release.md` — `/release`: `VERSION`, `CHANGELOG`, README, проверки,
  тег.
- `skills/project-kit/SKILL.md` — docs-baseline, каркас проектного `AGENTS.md`,
  ветки и версии.
- `templates/AGENTS.md`, `templates/PRD.md` — скелеты для нового проекта.
- `docs/prd/2.0.md`, `docs/workflow.md`, `TODO.md`.
- `install.sh` пишет манифест `harness-installed.txt`; `uninstall.sh` сносит по
  манифесту, с fallback на список файлов 1.0.0.
- `AGENTS.md`: правила про авто `git init`, ветки `feat/` `fix/` `docs/`
  `chore/`, SemVer, docs-baseline, обязательный каркас проектного `AGENTS.md`,
  язык общения, `doctor` и MCP-серверы: выключены глобально, включаются
  проектным `opencode.jsonc`.

### Changed

- `tests/verify.sh` читает эффективное состояние через HTTP API opencode
  (`/api/agent`, `/api/command`, `/api/skill`), а не через `opencode debug
  agent` и `opencode debug skill`, которых в 2.x нет.
- `permissions` вместо deprecated `permission`: упорядоченный ruleset
  `{action, resource, effect}`, действие `shell` вместо `bash`.
- `reviewer` ходит в `opencode/deepseek-v4-pro#high` с потолком `steps: 20`.
- Скиллы `tdd-workflow` (исходное состояние, проверка чувствительности, strict
  `xfail`) и `prd-authoring` (источники и допущения, `docs/prd/<slug>.md`).
- README перестроен: описание, установка, использование, архитектура, версии.

### Removed

- Поддержка opencode 1.x.

## [1.0.0] — 2026-11-15

Первый зафиксированный релиз: правила, агенты, команды, скиллы и установщик.

### Added

- `AGENTS.md` — семь правил, которые попадают в контекст каждой сессии: TDD
  без production-кода до падающего теста, PRD перед нетривиальной задачей, план
  до правок, атомарные диффы, реальные проверки, git только по явной просьбе,
  проверка git-репозитория на старте задачи и пиннинг зависимостей.
- `agents/implementer.md` — агент по умолчанию: TDD-цикл, реальные проверки,
  запрет на переписывание истории на уровне permissions.
- `agents/plan.md` — планировщик с `edit: deny`, только PRD или план.
- `agents/reviewer.md` — субагент-ревьюер на чтение, `edit: deny`.
- `commands/prd.md`, `commands/tdd.md`, `commands/review.md` — точки входа
  `/prd`, `/tdd`, `/review`.
- `skills/tdd-workflow/SKILL.md`, `skills/prd-authoring/SKILL.md` — процедуры,
  которые подгружаются по смыслу запроса.
- `install.sh` — установка в `~/.config/opencode` с бэкапом, проверкой
  `opencode` и `python3` до первой записи, наложением `opencode.json` поверх
  существующего конфига и идемпотентностью.
- `uninstall.sh` — снос файлов харнесса без потери провайдера и остального
  конфига.
- `tests/install.bats.sh` — 45 проверок установки, сноса, сохранения секретов,
  идемпотентности и отказов на битом входе.
- `tests/verify.sh` — проверка, что установленная конфигурация подхватилась.
- `LICENSE` — MIT.

### Compatibility

- Проверено на opencode 1.18.34 (Homebrew), `python3` 3.12, macOS 15.7.9
  arm64.

### Known limitations

- `tests/verify.sh` опирается на `opencode debug config` и
  `opencode debug agent`, которых нет в opencode 2.x, поэтому на 2.x он
  красный. Исправляется в 2.0.0.
- README и правила — инструкции для модели, а не enforcement. Реально
  блокируют только permissions.
- `default_agent: implementer` действует глобально, скрипты с явным `build`
  его не подхватывают.
- `uninstall.sh` содержит захардкоженные списки агентов, команд и скиллов:
  новый скилл придётся добавлять в двух местах.
