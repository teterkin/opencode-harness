# PRD: opencode-harness 2.4.0

**Goal** — правило про git опирается на корень репозитория, а не на факт его
существования: домашний каталог, оказавшийся git-репозиторием, больше не
считается проектом. `install.sh` предупреждает о такой машине при установке.

**Non-goals**

- Не менять `external_directory` и правила 12–13 из 2.3.0.
- Не чинить домашний репозиторий за пользователя: только предупредить.

**User story** — Как пользователь, у которого `$HOME` случайно оказался
git-репозиторием, я хочу, чтобы агент в новом проекте создавал локальный
репозиторий или спрашивал, а не коммитил в домашний и не тянул `.ssh` в индекс.

**Источники**

- `~/TEMP/session.log` (Linux, второй прогон): агент отказался коммитить,
  потому что `git rev-parse --show-toplevel` указал на `/home/teterkin`, и
  перечислил риски: `.ssh/`, `.git-credentials`, `.config/`. Предложил
  `git init` в проекте.
- Проверено на Mac: `git -C ~ rev-parse --show-toplevel` — «not a git
  repository», поэтому прежние тесты проблему не видели.

**Acceptance criteria**

1. В `AGENTS.md` правило 6 требует `git rev-parse --show-toplevel` и сравнения
   корня с рабочим каталогом.
2. В правиле 6 явно запрещены `git add -A`, `git add .`, `git commit -a` при
   корне в домашнем каталоге или `/`.
3. `install.sh` печатает предупреждение, если `$HOME` — git-репозиторий, и
   молчит, если нет.
4. `tests/install.bats.sh` проверяет и правило, и оба случая предупреждения.
5. README (правило 7 и список возможностей установки) описывает поведение.
6. `./tests/run.sh` зелёный.

**Risks**

- `$HOME` может быть симлинком; сравнение идёт через `pwd -P` с обеих сторон,
  иначе предупреждение ложно сработает или не сработает. На macOS `/tmp` —
  симлинк, тест это неявно проверяет.
- Предупреждение использует `git`; если его нет в `PATH`, проверка молча
  пропускается — установка от git не зависит.
