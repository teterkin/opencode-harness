# PRD: opencode-harness 2.7.0

**Goal** — зафиксировать ревью как один отдельный ручной проход: находки
возвращаются пользователю, правки идут отдельным решением, а автоматического
цикла «нашёл → починил → перетестил» и `/goal` нет.

**Non-goals**

- Автоматический цикл «нашёл → починил → перетестил» и `/goal` как способ его
  запускать.
- Агент-оркестратор, который сам решает, какие находки исправлять.
- Разрешать `reviewer` править файлы: он остаётся read-only.

**User story** — Как пользователь харнесса, я хочу читать находки ревьюера и сам
решать, что исправлять, чтобы аппрув результата оставался реальным контролем, а
не формальностью.

**Acceptance criteria**

1. В правиле 5 `AGENTS.md` сказано: ревью — один проход, исправления — после
   решения пользователя, повторный прогон — по просьбе, `/goal` и авто-цикл не
   используются.
2. `commands/review.md` требует сначала показать находки и не менять код до
   решения пользователя.
3. В `docs/workflow.md` есть подраздел «Ревью» с тем же контрактом.
4. README описывает ревью как один проход, а в «Известных ограничениях» называет
   отсутствие цикла решением, а не недоделкой.
5. `docs/prd/2.7.md` фиксирует эти non-goals.
6. `tests/docs.bats.sh` проверяет формулировки и отсутствие `/goal` в
   `commands/`; `./tests/run.sh` зелёный.

**Open questions**

- Нужен ли когда-нибудь opt-in `/fix` для авто-цикла — отложено. По умолчанию
  поведение остаётся ручным.

**Sources and assumptions**

- Прочитано: `commands/review.md`, `agents/reviewer.md`, `agents/implementer.md`,
  правило 5 `AGENTS.md`, `docs/workflow.md`, README (§«Ревью перед коммитом» и
  «Известные ограничения»), `tests/docs.bats.sh`.
- opencode 2.3.0: команда `/goal` встроена (`/api/command`, описание «keep
  working until an objective is met [pause|resume|clear]»), но в харнессе не
  используется.
- Допущение: интерактивность — требование пользователя, а не универсальное
  свойство харнесса. Поэтому причина живёт в PRD, а в правилах остаётся только
  контракт.

**Risks**

- Модель проигнорирует текстовое правило и всё равно начнёт исправлять:
  страховка — `commands/review.md` и явная просьба пользователя; permissions
  здесь не помогут.
- Жёсткий запрет автоматизации может помешать, если появится объективный
  критерий «ревью чисто». Тогда это будет отдельный PRD и opt-in команда, а не
  тихое изменение поведения.
