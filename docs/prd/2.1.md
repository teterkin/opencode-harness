# PRD: opencode-harness 2.1.0

**Goal** — установщик и шаблон конфига перестают навязывать `model` и
`default_agent`: выбранная пользователем модель переживает установку, а
проектный конфиг харнесса не перебивает глобальный выбор.

**Non-goals**

- Не пинить модель в агенте `implementer`: харнесс не выбирает модель за
  пользователя.
- Не трогать `reviewer` (`opencode/deepseek-v4-pro#high` остаётся) и
  `permissions`.

**User story** — Как пользователь с глобально выбранной
`opencode/deepseek-v4.1-flash`, я хочу, чтобы `implementer` работал на ней и в
репозитории харнесса, и после `./install.sh`, а не переключался на
`opencode/big-pickle`.

**Acceptance criteria**

1. `install.sh` сохраняет уже выбранные `model` и `default_agent`; дефолты
   `opencode/big-pickle` / `implementer` применяются только к отсутствующим
   ключам.
2. Шаблон `opencode.json` в репозитории не задаёт `model` и `default_agent`.
3. `tests/install.bats.sh` проверяет оба пункта и остаётся зелёным.
4. README описывает новое поведение и `opencode debug config` как способ
   увидеть, какой файл побеждает.
5. `VERSION` = верх `CHANGELOG.md` = тег `v2.1.0`.

**Open questions**

- Менять ли дефолт `opencode/big-pickle` на flash для пустого конфига —
  решено не менять.

**Risks**

- У пользователя без `model` в конфиге поведение не меняется: дефолт прежний.
- Дефолты переехали из шаблона в код `install.sh`; тест пустого конфига
  страхует от потери.

**Sources and assumptions**

- Прочитано: `opencode debug config`, `opencode debug agents`, `install.sh`,
  `opencode.json`, `tests/install.bats.sh`, `README.md`, `CHANGELOG.md`,
  документация opencode v2 по конфигурации.
- Проверено вживую: `opencode debug config` до и после правки, `./install.sh`
  на рабочем конфиге (model и default_agent сохранились).
